01 / JOB TYPE

「AIで350ページ作る」ではなく、版管理された小ロット製造として扱う

大量ページ制作で危険なのは、最後にまとめて欠落や共通ルール不良が見つかること。そこで、原稿とページの対応を保持し、少量でルールを検証してから、検品可能なバッチへ分けて製造する方式にしました。

原稿との追跡関係 ＋ 版管理テンプレート ＋ バッチ ＋ 二系統QA ＋ 二種類の戻り線。

02 / PROCESS

監査後の正解工程を、そのまま実装

01

追跡

SOURCE_IDとPAGE_IDで原稿と完成ページを対応付ける。

02

分類

COVER / EXPLAINER / DIAGRAM / CHECKLIST の4ページ型へ分類。

03

版管理

template 0.1で小ロット試作し、共通修正は0.2へ改版。

04

バッチ製造

B01=P001〜P004、B02=P005〜P008に分割して生成。

05

二系統QA

原稿照合と完成物検査を分離。内容欠落と表示異常を同じ箱に入れない。

06

戻り線

ページ固有不良は局所修正。共通規則不良はテンプレート改版後、影響ページを再検査。

03 / FAILURE → RECOVERY

完成画面ではなく、壊した時に戻れることを証拠にした

FAULT 01 / LOCAL

P005で原稿1ブロック欠落

trial版へ意図的に故障注入。

→ 原稿照合QAがP005だけを検出。

→ P005のみ局所修正。

FINAL: missing 0 / PASS

FAULT 02 / COMMON RULE

CHECKLIST型を9ptで生成

共通文字規則違反を注入。

→ P004 / P007を影響ページとして抽出。

→ template 0.2で11ptへ改版。

RETEST: P004 / P007 PASS

REAL FAILURE / RENDER

日本語字形の欠落を実発見

意図的故障ではなく最終レンダリング時に発生。

→ Noto Sans CJK JPへ共通修正。

→ 全8ページ再生成・再目視。

FINAL: FONT EMBEDDED

BREAK TEST

停止条件も別に試験

素材参照欠落はvalidatorでFAIL。

版不一致はversion markerで検出。

異常位置によって戻り先を変える設計を確認。
