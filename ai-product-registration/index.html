01 / JOB TYPE

AIの回答を人間が転記する工程を、機械が次工程へ渡せる形へ変える

登録事故の中心は、根拠のない補完、曖昧値の保存、二重登録、UI変更、保存後の値ずれです。そこで、人間向け文章を中継せず、Evidence付き構造化データをValidatorへ渡す設計にしました。

SOURCE PACKET → CANONICAL RECORD → Validator → Payload → Browser → Read-back → STATE LEDGER。

02 / PROCESS

保存前と保存後の両方で検品する

01

仕様固定

JOB SPEC / SOURCE PACKET / TARGET_SCHEMAを固定。

02

構造化

各fieldをvalue / evidence / statusで保持。

03

Validator

MISSING / CONFLICT / INFERRED等をREVIEWへ隔離。

04

Browser入力

05

二重Read-back

保存前に画面値、保存後に保存値を再取得して照合。

06

状態管理

SUCCESS / REVIEW / ERRORをSTATE LEDGERへ記録し、再実行位置を保持。

03 / FAILURE → RECOVERY
