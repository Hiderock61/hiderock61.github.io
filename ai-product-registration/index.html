01 / JOB TYPE

「AI回答を人がコピペ」ではなく、検品付き登録ラインとして設計

通常のAI利用では、AIが文章を出し、人が内容を読み、Webフォームへ転記します。この実演では、AI出力を人間向け文章ではなく、Evidence付きCANONICAL RECORDへ変換し、検証してからBrowserへ渡す構造にしました。

SOURCE PACKET → AI抽出 → Evidence Gate → Validator → TARGET_SCHEMA / Payload → Browser → 保存前後Read-back → STATE LEDGER。

02 / PROCESS

登録までを一筆書きで通す

01

SOURCE PACKET

商品テキストや画像メタデータを、商品単位で固定。

02

AI構造化抽出

各fieldを value / status / evidence で返す。

03

Evidence Gate

source_idと引用文が元SOURCE内に実在するか検査。

04

Validator

MISSING / CONFLICT / INFERREDをREVIEWへ隔離し、正常品だけ通す。

05

Payload / Browser

TARGET_SCHEMAへ変換し、フォーム入力後に保存前Read-back。

06

Save / 再照合

保存後値を再取得しCanonicalと比較。STATE LEDGERへ記録。

03 / FAILURE → RECOVERY

失敗を混ぜて、止まる場所を確認

REVIEW

必須素材が欠落

P003はmaterialがMISSING。

→ ValidatorでREVIEW。

Browser保存なし。

CONFLICT

色情報が衝突

P006はテキストと画像メタデータで色が不一致。

→ colorをCONFLICTとして隔離。

ERROR → RETRY

一時保存障害

P005へTRANSIENT_SAVE_FAILUREを注入。

→ 初回ERROR、再実行でSUCCESS。

BREAK TEST

UI欠損 / 保存後改ざん

#material削除はELEMENT_NOT_FOUNDで保存前停止。

保存値を故意に変えた試験ではpost-save mismatchを検出。
