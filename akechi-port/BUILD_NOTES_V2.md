# AKECHI PORT v2｜製作モード記録

## 固定成果物

`AKECHI PORT v2｜85外付け能力図鑑のWeb骨格 v0.1`

Notion正本 → `catalog-v2.json` → 静的HTML。第一利用者はヒデロック本人。説明書を作るのではなく、85能力を眺め、入力と出力から組み合わせを思いつける母型を作る。

## 想定故障と採用した対策

| 想定故障 | Web骨格へ残した対策 |
|---|---|
| 85件で情報過多 | 初期状態は要約だけ。詳細はカード単位で開く |
| 普通説明と設計説明が混ざる | 「人間視点」「設計副音声」の文字Labelと領域を分離 |
| 専門語が入口を塞ぐ | 上位分類は10の生活語。設計語は展開後の小Tag |
| 抽象説明で場面が浮かばない | すべてのカードに「本来の具体例」 |
| 接続が名前だけ | 接続先と「何を渡すか」を同じ行に表示 |
| Statusが主役になる | 右端の小Badge。説明本文より弱い |
| iPhoneで文字が小さい | 本文16px以上、一列化、ページ横スクロールなし |
| PCで横に長い | 本文幅1180px、人間／設計の2列だけを許可 |
| 大画面で階層不明 | Genre・Plugin名・視点Labelを大きさと間隔で区別 |
| 85長文が常時開く | `details/summary`による閉じた一覧 |
| 印刷でカード分断 | `break-inside: avoid`、印刷時だけ表示中カードを展開 |
| 単なる説明書になる | 冒頭説明を2文に限定し、各カードを「入力→出力→接続」で終える |

## 有識者会議を圧縮した決定

- 色彩：人間＝暖色、設計＝寒色、明智案＝緑。色に加えて必ず文字Labelを置く。
- 知覚：カードの読順を固定。要約から具体例、機械構造、アイデア、接続へ進む。
- 情報設計：10 Genreを上位分類にし、Sensor等はカード内部に置く。
- 元Web制作：85ページに分けない。1ページ＋Anchor＋検索＋Genre filter。外部ライブラリなし。
- 元Web編集：全Genreに「何ができるか」の一文を付ける。
- 文字組み：本文を小さくしない。大画面では最大幅を増やしすぎない。
- Accessibility：native details、Keyboard focus、Skip link、Contrast、文字Label。
- 構造：接続には受け渡す情報を書く。
- How to：閉じたカードに「詳しく見る」、接続先を次の閲覧導線にする。
- 劇団の現実圧：長い理論は画面へ載せず、85件を見る気を削がない密度にする。
