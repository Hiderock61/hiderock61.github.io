1｜雪だるま法©️の新しい説明

仕事を一工程ずつ実行し、以前の能力・道具・データ・失敗履歴を継承しながら、不足する能力だけをPluginや既存装置から探して接続する。入力から出力までを検証し、成功した装備を次の仕事へ増やしていく複利型の実行方法。

案件を食べる → 動詞分解 → 旧装備を再利用 → 不足能力を探索 → Pluginの内部機構を照合 → 入出力を配線 → 最小実行 → QAと証拠 → 装備へ帰還 → 次の案件へ

原点は「一個動かす → 結果を見る → 次を発見する」。この原点を置き換えず、外付け能力と搬送監査を加えました。

2｜太った君©️は何者？

雪だるま法©️で獲得した専門能力の呼び名、再利用コード、Plugin接続経路、入出力形式、実機証拠、失敗時の停止条件をひとまとめにした「装備付き実行体」。

独立したAIが何人も常駐する意味ではありません。カードの「あだ名」は、実行できる能力パッケージの人間向けインターフェースです。

装備を脱がない原則

旧Feed・攻略装置・成果物047・049・AKECHI PORT・実験部品を維持し、その案件で必要な機能だけ召喚。使わない機能も消さない。

2026-10-13時点：中央名簿9能力＋追加名簿2能力＝呼び出し候補11パッケージ。追加2件は小型SELF DEMO。案件実験番号や実顧客納品件数と混ぜません。

3｜Plugin装着を支える三人

🥷 HOWTOザムライ

依頼を「探す・読む・照合・入力・再読」など1動詞ずつに切る。1動詞＝1能力照合単位。

🤖 自己認識明智くん

今使える旧装備・Plugin・外付けツールを証拠付きで照合。足りない工程だけDISCOVERへ回す。

🤩 平賀カラクリ

Pluginを Input → 処理 → Output へ分解し、出力が次の専門装置の入力へ届くよう配線する。

役者は方法の作業分担を表す呼称。必要に応じて探偵AI・検品主任・人間の最終確認を加えます。

4｜外付け能力の棚

  1. 成果物049：技術Feed001〜051・旧攻略装置・雪だるま資産の索引。再発明を避ける。
  2. 成果物047：既存Plugin/Toolの実機証拠と接続ランタイム。
  3. AKECHI PORT：Pluginの内部機構と入出力、権限、状態変化を分解した図鑑。
  4. 成果物048：分解済みPluginの動詞を現在の案件へ逆引きするカード。
  5. 能力名簿：あだ名・固有キー・INPUT/OUTPUT・実証成熟度・未実証条件を保持。

Plugin名を先に選ばない。「何の動詞が足りない？」を起点に必要分だけ候補を選びます。

5｜今回の実験で分かったこと

ココナラ公開依頼 #5317978 を材料に、MiniFishとExa PluginのREAD経路を比較しました。

経路観測結果判定
MiniFishGitHub Actionsは完走。対象ブラウザは403 Forbidden。本文読取HOLD
Exa Search同題名の別案件 #5227889 が先頭に登場。案件ID違いで停止
Exa Fetch正しいURL #5317978 を指定して募集本文を取得。対象READ成功
商品監視実際のフリマ商品一覧・顧客台帳は渡されていない。未実証

証拠：MiniFish結果と403記録。Exaは今回の会話で実行した本文抽出。公開ページの取得と顧客業務の完了は別です。

6｜「装着成功」に必要なチェック

  1. 対象の仕事IDと元URLが一致している。
  2. 必要動詞へ旧能力／Pluginを対応付けている。
  3. 入力元 → ツール → 出力先へデータが実際に運ばれた。
  4. READ、WRITE、外部送信、課金、公開を別権限で監査している。
  5. 出力・エラー・再読の証拠が残っている。403や不完全データはHOLD。
  6. 追加能力の固有INPUT/OUTPUTと合格試験を保存し、別案件で再利用可能になった。

実物なしなら「設計候補」、検索結果だけなら「発見」、実機通過なら「動詞単位のPROVEN」。有料業務の成功は顧客納品の証拠が別途必要です。
